# A/B 对照验证结果

方法：同一套「提取根因证据」流程，对比 **低层细粒度工具 vs 高层抽象原语**。

## 第一/二轮：同后端低层 raw vs 高层抽象（n=9 崩溃样本）

| 指标 | A 组（低层） | B 组（高层） | 对比 | PRD 门槛 |
|------|-------------|-------------|------|---------|
| Tool Calls | 90 | 27 | **-70%** ✅ | -30% ✅ 远超 |
| 输出 bytes（token 代理） | 11,136 | 13,711 | **+23%** ≈ 持平 | -20% 未完全达标 |
| 证据完整率 | 9/9 | 9/9 | 持平 ✅ | — |

## 第三轮（2026-08-22）：真实 token 计量——同模型双策略（本会话）

subagent 独立会话方案因 DSH subagent LLM 通道超时不可用，改为**同一模型
（deepseek-v4-flash）分两个受控阶段**：阶段 A 用高层聚合原语（launch/run/terminate，
run 返回 after-state 自带寄存器/回溯/反汇编），阶段 B 用细粒度原语
（launch/run/disassemble/get_register/read_memory/terminate，禁用 observe 等聚合工具）。
任务：阶段 A=crash_target（NULL 写），阶段 B=unknown_target（index*2 溢出越界读），
两阶段均正确定位根因。token 用 `scripts/ab_split.py` 从 session 日志的 provider usage
精确计量（非字符代理）。

| 指标 | A（高层） | B（低层） | 比值 |
|------|----------|----------|------|
| 核心调试操作 | 3 | 6 | **2x** |
| 工具调用（含写报告） | 4 | 7 | 1.8x |
| output tokens | 773 | 2,734 | **3.5x** |
| reasoning tokens | 170 | 1,551 | **9.1x** |
| input tokens | 1,099 | 2,172 | 2.0x |
| 成功率 | ✓ | ✓ | — |

**结论（诚实版）**：真实 token 计量证实高层抽象在推理/输出 token 上省 3–9x（同模型、同后端、
真 provider usage）。局限：单任务、小样本；同会话两阶段（非独立 agent，存在上下文影响——
但目标不同，答案未泄漏）；cacheRead 不可比（会话位置不同）；我是同一模型扮演两种策略
（观察者效应存在）。方向与第一/二轮（tool calls -70%）一致，互相印证。

## 结论（第一/二轮，n=9）

1. **核心假设 H2 成立且稳健**：高层抽象把「拿同一份根因证据」从 10 次调用压到 3 次（-70%），
   两轮不变，远超 PRD -30% 门槛。
2. **Token 已基本持平**：+23% 主要来自 launch 返回了「停在哪/为什么停」的元数据（低层返回裸 pid，
   要拿到同样信息得多 2 次调用），以及少量空字段开销。此度量**未计**工具定义 schema：
   高层 16 个工具 < 低层 20+ 个，真实 LLM token 层面高层很可能更省——第三轮真实 token 计量
   证实了这一推测（output/reasoning 省 3–9x）。
3. **价值主张成立**：调用次数 -70% 是硬收益（往返少、agent 拼错状态概率低），token 不亏。

## 剩余边界

- **Token 精确计量**：第三轮已用 session 日志 provider usage 实现（`scripts/ab_split.py`）；
  跨模型对照（Claude Code）仍需外部环境。
- **未覆盖样例**：condbp（条件断点）、threads（多线程枚举）需要条件断点/线程枚举能力，属特性而非抽象层级。
- **真 x64dbg MCP 对照组**：本轮用「同后端低层 raw」隔离抽象变量（更严谨）；拿真 x64dbg MCP 对照需先无头化
  x64dbg（M1 已论证脆），可作后续。
